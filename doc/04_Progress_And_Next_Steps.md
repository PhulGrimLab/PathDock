## 5. 탐색기 화면 구성 (2026-10-12 추가)

`[드라이브 목록] | [조부모 폴더 열] | [부모 폴더 열] | [현재 폴더 목록(이름/수정일/크기/하위 항목)] + 요약 줄`
(열 사이는 GridSplitter로 폭 조절)

- 드라이브: 사용량 막대/문구, 클릭 시 루트로 이동, 현재 드라이브 강조.
- 상위 2단계 열(Mdir 스타일): 부모/조부모 폴더의 하위 폴더를 나열하고 현재 경로가 지나는 폴더를 선택 표시. 다른 폴더를 누르면 이동.
- 현재 목록: 폴더는 전체 크기와 "파일 N · 폴더 M"을 백그라운드로 채운다. 요약 줄: "폴더 n개 · 파일 m개 (크기) · 전체 크기".
- 파일 더블클릭/Enter: 셸 연결로 열기 — exe/cmd는 실행, 이미지·문서·영상 등은 Windows 기본 프로그램으로 열린다. 작업 폴더는 파일이 있는 폴더, UAC 취소는 오류로 표시하지 않는다.

## 6. 폴더 크기 캐시 (`FolderSizeCache`)

- 저장: 메모리 + `%APPDATA%\PathDock\folder-size-cache.json`(종료 시 저장, 시작 시 로드, 손상되면 빈 캐시, 최대 5000개).
- 키: 정규화한 경로(대소문자/후행 `\` 무시). 값: 크기·파일 수·폴더 수·불완전 여부·계산 시각·폴더 수정 시각.
- **Fresh**(30분 이내 + 폴더 자신의 수정 시각 동일): 재계산 없이 즉시 표시.
- **Stale**(오래됨/폴더 변경): 값을 먼저 보여주고 `(갱신 중)`을 붙인 채 백그라운드로 재계산.
- **Missing**: "계산 중…" 후 계산.
- **새로 고침 버튼**은 캐시를 무시하고 강제 재계산한다.
- 한계: 폴더 자신의 수정 시각은 깊은 하위 변경을 반영하지 못하므로 30분 TTL이 상한선이다. 파일 조작 기능이 생기면 `Invalidate(path)`를 호출해야 한다(구현만 되어 있음, 아직 호출처 없음).

## 7. 하단 시스템 사용량 (`SystemMonitor`)

- 2초마다 측정, 오른쪽 하단에 `CPU n% | GPU n% | 메모리 사용 / 전체 (n%)`.
- CPU: `GetSystemTimes` 증분. 메모리: `GlobalMemoryStatusEx`. GPU: 성능 카운터 `GPU Engine\Utilization Percentage`를 엔진 종류별로 모든 프로세스 합산 후 최댓값(작업 관리자 방식). 카운터가 없는 환경은 `N/A`.
- GPU가 여러 개여도 전체 중 최댓값 하나만 표시한다(GPU별 구분 없음). 측정 비용은 백그라운드 스레드에서 처리한다.

## 8. 열 머리글 정렬과 파일 조작 (2026-10-13 추가)

- **정렬**: 이름/수정한 날짜/크기 머리글 클릭 → 같은 열이면 오름↔내림 전환, 머리글에 ▲▼ 표시. 항상 폴더가 먼저, 이름은 자연 정렬(file2 < file10, 대소문자 무시), 동률은 이름순. 크기 정렬 중에는 폴더 크기가 모두 확정된 뒤 한 번 재정렬한다(계산 중 행이 계속 움직이지 않도록). 크기를 모르는 폴더는 가장 작은 값으로 취급.
- **이름 변경(F2 / 우클릭)**: 입력창에서 규칙 검증(금지 문자, 끝의 `.`/공백, 중복 이름), 대소문자만 바꾸는 이름 변경 지원, 성공하면 새 항목 선택.
- **삭제(Delete / 우클릭)**: 확인 창(기본 "아니오") 후 **휴지통**으로 보낸다(영구 삭제 아님).
- **새 폴더(Ctrl+Shift+N, 목록에 포커스가 있을 때 / 우클릭)**: "새 폴더", "새 폴더 (2)" 식으로 기본 이름 제안.
- 조작이 성공하면 해당 폴더와 **모든 상위 폴더**의 크기 캐시를 무효화하고 목록을 새로 읽는다(`FolderSizeCache.InvalidateWithAncestors`). 실패(권한/중복 등)는 InfoBar에 사유와 함께 표시.
- 터미널에 포커스가 있을 때의 키(F2, Delete, Ctrl+Shift+N)는 터미널로 간다 - 탐색기 단축키는 목록에 포커스가 있을 때만 동작한다.

## 16. 시작 로딩 팝업 (2026-10-16)

상세는 [05_UI_Design.md](./05_UI_Design.md) 4.1절.

- **배경**: 단일 파일 배포본(`publish\Release\PathDock.App.exe`)은 실행 후 메인 창이 보이기까지 약 4.1~4.4초(3회 측정, 반복 실행에도 비슷 — 첫 실행만의 문제가 아님). 그동안 아무 반응이 없어 로딩 안내가 필요했다.
- **기능**: "로딩 중..." 팝업(로고, 제목, **지금 하는 일 한 줄**, **계속 흐르는 진행 막대**). 설정/언어를 읽은 직후 가장 먼저 띄우고, 단계마다 문구를 바꾸고(`테마와 글꼴 적용 중...` → `폴더 크기 캐시 불러오는 중...` → `탐색기와 터미널 준비 중...` → `화면 구성 중...` → `폴더 목록 읽는 중...` → `터미널 시작 중...` → `준비 완료`), 메인 창이 그려진 뒤 1초 후 닫는다.
- **구현 변천**: ① WPF 창을 UI 스레드에 둠(막대가 UI 스레드가 막히면 멈춤) → ② 별도 UI 스레드의 WPF 창 → ③ **순수 Win32 창**(전용 스레드 + GDI + 타이머, `Services/SplashHost.cs`)으로 확정. 막대 정지 여부를 PowerShell 스크립트로 재다가 **스크립트가 DPI 비인식이라 창 크기를 축소해 읽고 왼쪽 위만 캡처**하는 오류가 있었다(막대가 없는 영역을 비교). ②에서 "멈춘다"고 본 판단은 이 오류의 영향을 받아 WPF 방식 자체의 한계는 정확히 검증하지 못했다. Win32 방식은 DPI 인식으로 다시 측정해 **매 프레임 움직임을 확인**했다(Debug 19/19, Release 배포본 17/17 프레임이 모두 다른 화면).
- **측정(Debug, 로그)**: `OnStartup` 진입 1.6초 → 팝업 표시 약 1.8~2.0초 → 메인 창 표시 완료 4.7초. **팝업이 덮는 구간은 약 2초 이후**이고, 앞의 약 2초(런타임·WPF 리소스 로딩)는 덮지 못한다. WPF 내장 `SplashScreen`을 써도 단일 파일 압축 해제(`Main` 이전)는 덮지 못한다. 아직 시도하지 않았다.
- **테스트**: UI `Startup_ShowsLoadingPopup_AndClosesAboutOneSecondAfterMainWindow`(먼저 뜸, 메인 창이 뜬 시점에도 보임, 0.7~5초 사이에 닫힘), `Startup_LoadingPopup_BarKeepsMovingAndStatusLineChanges`(초기화 중 실제 화면의 막대가 계속 다르고 문구가 단계별로 바뀌며 마지막이 "준비 완료"). 후자는 **막대 타이머를 일부러 느리게 한 결함 주입에서 실패하는 것을 확인**했다(8장 중 1종). 전체 UI 25/25, MSTest 112/112 통과.
- **하네스 변경**: 메인 창을 제목으로 찾고, 닫기도 제목으로 찾은 메인 창에 보낸다(`CloseMainWindow`는 시작 직후 로딩 팝업을 메인 창으로 오인해 닫기 테스트가 실패함). 하네스 프로세스를 DPI 인식으로 만들고 막대 판정은 PrintWindow가 아닌 실제 화면 캡처로 한다(doc/03 4절 8~10번).
- 화면은 다크 테마의 Debug 빌드와 Release 단일 파일 배포본에서 확인했다.

## 21. PDF 미리보기 복구 (2026-10-17)

PDF 파일 위에서 미리보기가 뜨지 않는다는 지적으로 확인했더니, 기능은 이미 `main` 브랜치의 커밋 `148a65c`("PDF 썸네일, 문서 일반 권한 열기, 문서 최신화", 2026-10-13)에서 만들어져 있었고 작업 브랜치(`feature/pathdock-mvp`)는 그 커밋을 받지 못한 상태였다(두 브랜치가 `79be7b1`에서 갈라짐).

- **가져온 것(체리픽, 코드·테스트만)**: `PdfPreviewService`(Windows.Data.Pdf, 첫 쪽 가로 240px, 흰 배경, 쪽수 표시), `UnelevatedLauncher`+`LaunchPolicy`(문서·이미지는 탐색기를 통해 일반 권한으로 열어, 관리자 권한 앱에서 Adobe Reader 등이 반응 없던 문제 해결), 앱 대상 프레임워크 `net10.0-windows10.0.19041.0`, `ImagePreviewTypes` PDF 판별과 단위 테스트(+2), 하네스 `AppDriver`의 앱 경로 탐색.
- **가져오지 않은 것**: `148a65c`의 문서 변경(README, doc/00~05, 기획서). 이 브랜치의 문서와 갈래가 달라 충돌이 많아, 필요한 PDF/프레임워크/실행 권한 내용만 이 브랜치 문서에 직접 반영했다. `main`의 문서 갱신분은 나중에 병합할 때 따로 정리해야 한다.
- **검증**: 임시 하네스에서 2쪽짜리 PDF를 렌더링(240×311, 쪽수 2), 암호 대신 손상된 파일과 없는 파일은 null로 안전하게 처리, 같은 파일 재요청은 캐시 사용. 전체 MSTest 208개, UI 33/33 통과. 툴팁이 화면에 뜨는 모습은 마우스 호버가 필요해 직접 확인하지 못했다.
- **브랜치 정리 (2026-10-17)**: 위와 같은 일이 되풀이되지 않도록 작업 브랜치를 `main`에 병합해 한 갈래로 합쳤다. 문서는 작업 브랜치(현재 코드) 기준으로 두고, `main`에만 있던 내용 중 현재도 맞는 것(README의 다운로드/라이선스, doc/00 릴리스 상세, doc/01 6~8절 다국어·미리보기 흐름·파일 열기와 권한, 기획서 9절 구현 현황)을 옮겨 적었다.

## 23. 중복 실행 방지 (2026-10-20)

**문제**: 같은 데이터 폴더로 앱을 두 번 실행하면 둘 다 떴다(재현 확인). 설정·폴더 크기 캐시·로그 파일을 두 인스턴스가 함께 써서, 나중에 닫은 쪽이 먼저 닫은 쪽의 변경(즐겨찾기, 창 위치 등)을 덮어쓸 수 있고 터미널·자원도 두 배로 쓴다.

**동작**: 같은 데이터 폴더(`PATHDOCK_DATA_DIR` 또는 `%APPDATA%\PathDock`)로 이미 떠 있으면, 두 번째 실행은 로딩 팝업도 띄우지 않고 기존 창을 앞으로 가져온 뒤(최소화돼 있으면 복원) 종료 코드 0으로 바로 끝난다. 데이터 폴더가 다르면(UI 테스트, 개발용) 따로 뜰 수 있다.

**구현**: `SingleInstanceGuard`(App) - 이름 있는 Mutex(`Local\PathDock-<경로 해시 16자리>`)로 첫 인스턴스를 가리고, 이름 있는 자동 초기화 이벤트(`...-show`)로 "앞으로" 신호를 보낸다. 신호는 첫 인스턴스의 창이 준비되기 전에 와도 기억했다가 창이 뜬 뒤 한 번 처리한다. 두 번째 실행은 `AllowSetForegroundWindow`로 첫 인스턴스가 포그라운드로 나올 수 있게 허용한다. 이름은 Core의 `SingleInstanceName`(경로의 대소문자·끝 구분자 무시, SHA-256 앞 8바이트)이 만들고 MSTest 4개로 확인한다. 첫 인스턴스가 비정상 종료해 Mutex가 버려진 경우(AbandonedMutexException)는 이어받아 새로 뜬다(강제 종료 후 재실행으로 확인).

**테스트**: UI 3개(같은 폴더 → 두 번째 종료·첫 창 유지, 최소화된 창 복원, 다른 폴더 → 둘 다 실행).

**알려진 사항**: 이름 있는 객체를 만들 수 없는 예외적인 경우(권한 등)에는 막지 않고 그대로 실행한다. 두 번째 실행에는 안내 메시지를 따로 보이지 않는다(창이 앞으로 나오는 것으로 충분하다고 판단).

## 24. 폴더 영역 3가지 배치 (2026-10-29)

**요구**: 폴더 탐색기 영역을 4개로 나눠 각각 다른 폴더를 보거나, 두 묶음(상위 폴더 열 + 폴더)으로 보거나, 지금처럼 한 경로(상위 폴더 3개 + 현재 폴더)로 볼 수 있게 한다.

| 배치 | 모양 | 상위 폴더 열 | 경로 탭(파란 주소 표시줄) |
|---|---|---|---|
| 4분할 | 폴더 4개를 2열 2행 | 없음 | 위 두 개는 맨 윗줄(기존 위치), 아래 두 개는 각 폴더 바로 위 |
| 2묶음 | 묶음 2개 나란히(분할 막대 없이 50:50) | 묶음마다 폭이 좁은 열 1개 | 맨 윗줄(기존 위치)에 묶음마다 하나 |
| 한 경로 (기본값, 기존 모습) | 폴더 1개 | 3개(증조부모·조부모·부모) | 맨 윗줄(기존 위치) |

- 배치 버튼 3개는 **제목 표시줄 가운데**, 높이·세로 위치는 계산기 버튼 등 오른쪽 버튼과 같다(33px/125% 배율). 선택된 배치는 강조색 채움 + 흰 아이콘 + 폴더 선택과 같은 앰버 링(`PdPaneActiveBrush`)으로 표시하고, 선택 안 된 버튼은 아이콘을 흐리게 한다. 링은 오버레이다(**테두리 두께를 1→2로 바꾸면 제목 표시줄 안에서 첫 버튼 왼쪽 위가 잘려 보이는 잔상이 생겼다**). 구현은 `TitleBar.CenterContent` 안에 두며, 위치는 제목 표시줄 가운데 칸을 그대로 따른다(예전에는 렌더 변환으로 창 정중앙에 맞췄으나 좁은 창에서 시계와 겹쳐 제거함). **겹쳐 올린 버튼은 실제 마우스로 눌리지 않았다**(Windows가 제목 표시줄 영역을 창 이동으로 처리하며 `WindowChrome.IsHitTestVisibleInChrome`·`WM_NCHITTEST` 훅으로도 해결되지 않음). UIA `Select`로는 눌려 보여 놓치기 쉬우니, 이 영역을 고칠 때는 실제 마우스 클릭으로 확인할 것.
- **선택된 폴더 영역**: 클릭하거나 포커스가 들어오면 선택되고(처음/선택 없음은 왼쪽 위), 카드 바깥에 3px 테두리가 생긴다. 색은 테마별 `PdPaneActiveBrush`(다크 앰버 `#FFC83D`, 라이트 진한 주황 `#D9480F`, 고대비는 시스템 강조색)로 파란 경로 탭과 겹치지 않게 했다. 테두리는 오버레이라 레이아웃 공간을 차지하지 않아, **폴더 카드의 좌우 끝이 경로 탭의 좌우 끝과 같다**(한 경로 배치는 영역이 하나뿐이라 테두리 없음). 이동 버튼·즐겨찾기·드라이브 표시·**터미널 연동**은 모두 선택된 영역에 적용된다. 선택을 바꾸면 터미널도 그 영역의 폴더로 따라간다(동기화 모드가 허용할 때).
- **저장/복원**: `settings.json`에 `Layout`(이름으로 저장), `PanePaths`(영역 4개의 마지막 경로), `ActivePane`, `QuadExplorerRatio`를 저장하고 시작할 때 읽는다. 경로가 사라졌으면 사용자 폴더, 저장된 적이 없는 영역은 마지막 경로에서 시작한다. 이전 버전 설정 파일은 한 경로 배치 그대로 열린다.
- **4분할 영역 구분**: 영역(경로 탭 + 폴더) 사이를 16px로 띄우고(탭-폴더 간격 8px보다 넓게) 간격 가운데에 1px 십자 선(`ControlStrongStrokeColorDefaultBrush`)을 그었다. 위쪽 탭 줄의 세로선은 본문 세로선으로 이어진다.
- **배치 전환 속도**: 처음에는 배치마다 DataTemplate을 바꿔 `PaneView`를 새로 만들었는데, 전환에 Release 기준 0.4~1.4초가 걸렸다(`FileListView`가 무겁다). 지금은 폴더 영역 4칸과 윗줄 경로 탭 4개를 한 번만 만들어 두고 `MainWindow.ApplyPaneLayout`이 위치·보임·상위 열 수만 바꾼다(56~270ms). 안 보이는 칸은 Collapsed라 UIA 트리에도 없다. 한 경로 배치는 선택된 영역의 칸만 보인다.
- **터미널 위치**: 4분할은 탐색기를 더 크게(기본 78%) 두어 터미널이 아래로 내려간다. 배치별로 비율을 따로 기억하며 4분할 ↔ 다른 배치 전환 때 서로 바뀐다.

### 구현
- `MainViewModel`이 `ExplorerViewModel` 4개(`Panes`)를 갖고, 선택된 영역을 `Explorer`로 노출한다(기존 바인딩·즐겨찾기·드라이브가 그대로 동작). `PathSyncService`는 그때그때 선택된 영역을 가리키는 `ActivePaneTarget`을 받는다.
- 보이지 않는 영역은 시작할 때 읽지 않고(`_pendingPaths`) 처음 보일 때 이동한다. 상위 폴더 열은 보이는 개수(`SetAncestorDepth`: 4분할 0, 2묶음 1, 한 경로 3)만큼만 디스크를 읽는다. 배치별 템플릿은 `ContentControl`이 하나만 만든다.
- 숨김 파일 표시는 모든 영역에 공통이다. UI Automation ID는 첫 영역이 기존 그대로(`PathBar`, `FileList`, `AncestorColumn_1`…), 나머지는 `_P2`~`_P4` 접미사.
- 2묶음은 윗줄 경로 탭과 열이 어긋나지 않게 **분할 막대를 두지 않고 50:50 고정**이다(요구가 바뀌면 재검토).
- 2묶음에서는 앞의 두 영역만 보인다. 영역 3·4를 선택한 채 2묶음으로 바꾸면 첫 영역이 선택된다. 한 경로는 선택된 영역을 보여준다.

### 테스트
- 단위 7개 추가(`PaneLayoutSettingsTests`: 기본값, 구버전 파일, 저장·로드 왕복, 손상 값 보정, QuadExplorerRatio) — 전체 242 통과.
- UI 3개 추가: 배치 버튼 전환(영역 수·상위 열 수), 영역 클릭 선택 → 터미널 추종 + 이동 버튼이 선택 영역에만 적용, 재시작 후 영역별 경로·배치·선택 복원.
