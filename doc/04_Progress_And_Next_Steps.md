## 3. 이번 개발에서 실측으로 발견·수정한 문제 (회귀 테스트 있음)

| 문제 | 원인 | 수정 |
|---|---|---|
| 자식 PowerShell이 곧바로 종료, 화면 비어 있음 | 호스트 stdout이 리다이렉트되면 ConPTY 대신 상속 | `STARTF_USESTDHANDLES` 지정 (doc/02 2.1) |
| 화면에 `#< CLIXML` 출력 | `-EncodedCommand` | 임시 `.ps1` + `-File` |
| OSC 9;9/133 신호 유실 | PS 5.1 콘솔 VT 모드 꺼짐 | 창 제목 `PD:n:경로` 마커 (doc/02 3절) |
| `\|` 등 잘못된 경로가 정규화 통과 | `GetFullPath`가 검사 안 함 | `PathNormalizer`에서 직접 거름 |
| 설정 저장 예외 | `double.NaN`은 JSON 불가 | `double?` |
| 즐겨찾기 이름의 `_`가 사라짐 | 버튼 문자열 Content → AccessText | `TextBlock`으로 감싸기 |
| 폴더 접근 거부가 빈 목록으로 조용히 표시 | `IgnoreInaccessible = true` | false로 바꿔 오류 표시 |
| UI 테스트 간헐 실패 | 앱이 포그라운드가 아닌 채 `SendKeys` | `Native.BringToFront` |

5. `PathDock` 명칭 중복/상표 확인(기획서 7절) 미수행 — 사람이 확인해야 함.

8. **폴더 크기 계산 비용**: 하위 폴더가 큰 곳(예: `C:` 루트)을 처음 열면 오래 걸린다. 3개씩 병렬, 이동하면 취소, 완료되는 대로 표시한다. 두 번째부터는 캐시(5절)로 즉시 보인다. 접근 불가 항목이 있으면 크기 뒤에 `+`, 링크/정션은 따라가지 않는다.
7. CI: 릴리스 워크플로(`release.yml`)만 있다(테스트+빌드+릴리스). UI 테스트는 데스크톱 세션이 필요해 GitHub의 러너에서는 돌리지 않는다.

## 5. 탐색기 화면 구성 (2026-10-12 추가)

`[드라이브 목록] | [조부모 폴더 열] | [부모 폴더 열] | [현재 폴더 목록(이름/수정일/크기/하위 항목)] + 요약 줄`
(열 사이는 GridSplitter로 폭 조절)

- 드라이브: 사용량 막대/문구, 클릭 시 루트로 이동, 현재 드라이브 강조.
- 상위 2단계 열(Mdir 스타일): 부모/조부모 폴더의 하위 폴더를 나열하고 현재 경로가 지나는 폴더를 선택 표시. 다른 폴더를 누르면 이동.
- 현재 목록: 폴더는 전체 크기와 "파일 N · 폴더 M"을 백그라운드로 채운다. 요약 줄: "폴더 n개 · 파일 m개 (크기) · 전체 크기".
- 파일 더블클릭/Enter: 셸 연결로 열기 — exe/cmd는 실행, 이미지·문서·영상 등은 Windows 기본 프로그램으로 열린다. 작업 폴더는 파일이 있는 폴더, UAC 취소는 오류로 표시하지 않는다.

## 6. 폴더 크기 캐시 (`FolderSizeCache`)

- 저장: 메모리 + `%APPDATA%\PathDock\folder-size-cache.json`(종료 시 저장, 시작 시 로드, 손상되면 빈 캐시, 최대 5000개).
- 키: 정규화한 경로(대소문자/후행 `\` 무시). 값: 크기·파일 수·폴더 수·불완전 여부·계산 시각·폴더 수정 시각.
- **Fresh**(30분 이내 + 폴더 자신의 수정 시각 동일): 재계산 없이 즉시 표시.
- **Stale**(오래됨/폴더 변경): 값을 먼저 보여주고 `(갱신 중)`을 붙인 채 백그라운드로 재계산.
- **Missing**: "계산 중…" 후 계산.
- **새로 고침 버튼**은 캐시를 무시하고 강제 재계산한다.
- 한계: 폴더 자신의 수정 시각은 깊은 하위 변경을 반영하지 못하므로 30분 TTL이 상한선이다. 파일 조작 기능이 생기면 `Invalidate(path)`를 호출해야 한다(구현만 되어 있음, 아직 호출처 없음).

## 7. 하단 시스템 사용량 (`SystemMonitor`)

- 2초마다 측정, 오른쪽 하단에 `CPU n% | GPU n% | 메모리 사용 / 전체 (n%)`.
- CPU: `GetSystemTimes` 증분. 메모리: `GlobalMemoryStatusEx`. GPU: 성능 카운터 `GPU Engine\Utilization Percentage`를 엔진 종류별로 모든 프로세스 합산 후 최댓값(작업 관리자 방식). 카운터가 없는 환경은 `N/A`.
- GPU가 여러 개여도 전체 중 최댓값 하나만 표시한다(GPU별 구분 없음). 측정 비용은 백그라운드 스레드에서 처리한다.

## 8. 열 머리글 정렬과 파일 조작 (2026-10-13 추가)

- **정렬**: 이름/수정한 날짜/크기 머리글 클릭 → 같은 열이면 오름↔내림 전환, 머리글에 ▲▼ 표시. 항상 폴더가 먼저, 이름은 자연 정렬(file2 < file10, 대소문자 무시), 동률은 이름순. 크기 정렬 중에는 폴더 크기가 모두 확정된 뒤 한 번 재정렬한다(계산 중 행이 계속 움직이지 않도록). 크기를 모르는 폴더는 가장 작은 값으로 취급.
- **이름 변경(F2 / 우클릭)**: 입력창에서 규칙 검증(금지 문자, 끝의 `.`/공백, 중복 이름), 대소문자만 바꾸는 이름 변경 지원, 성공하면 새 항목 선택.
- **삭제(Delete / 우클릭)**: 확인 창(기본 "아니오") 후 **휴지통**으로 보낸다(영구 삭제 아님).
- **새 폴더(Ctrl+Shift+N, 목록에 포커스가 있을 때 / 우클릭)**: "새 폴더", "새 폴더 (2)" 식으로 기본 이름 제안.
- 조작이 성공하면 해당 폴더와 **모든 상위 폴더**의 크기 캐시를 무효화하고 목록을 새로 읽는다(`FolderSizeCache.InvalidateWithAncestors`). 실패(권한/중복 등)는 InfoBar에 사유와 함께 표시.
- 터미널에 포커스가 있을 때의 키(F2, Delete, Ctrl+Shift+N)는 터미널로 간다 - 탐색기 단축키는 목록에 포커스가 있을 때만 동작한다.

## 11. 사용성 개선과 터미널 기능 (2026-10-13)

- **탐색기**: 다중 선택(Ctrl/Shift), 복사·잘라내기·붙여넣기(Ctrl+C/X/V, 같은 이름은 "- 복사"), 이름 검색(Ctrl+F), 즐겨찾기 우클릭 편집(이름 바꾸기·좌우 이동·비우기),
  파일 목록 Backspace=상위 폴더. 열 폭은 글자 크기·창 폭에 맞춰 자동 조정(이름 열이 남는 폭을 채움).
- **터미널**: 셸 선택(PowerShell/cmd), 마우스 선택·복사·붙여넣기, 색 테마 5종 + 직접 지정, 내용 저장, 화면 지우기, 여러 줄 붙여넣기 확인 (doc/02 7절).
- **제목 표시줄**: 계산기(이미 떠 있으면 새로 만들지 않고 그 창을 앞으로) · 휴지통 비우기(항목 수/용량 확인) · 설정 · 테마 · 버전과 빌드 날짜. 단축키 Ctrl+Alt+C / Ctrl+Alt+E.
- **폴더 크기 표시 상한**: 폴더 집계는 5 GB에 이르면 멈추고 "5 GB 이상", 개수는 1000개 이상이면 "1천개 이상"(영어: "1,000+"). 요약의 전체 크기도 "이상"으로 표시.
- **미리보기 툴팁**: 이미지(썸네일 240px + 해상도/크기)와 텍스트·소스(앞 20줄) — doc/01 7절.
- **관리자 권한 실행**(`app.manifest`), 이름 변경/삭제 등 확인 창은 앱 글꼴을 쓰는 자체 대화상자(`ConfirmDialog`)로 교체(시스템 메시지 상자의 `\`가 `₩`로 보이던 문제).

- **PDF**: 첫 쪽 썸네일 툴팁(Windows 내장 PDF 렌더러, 쪽수 표시). 문서는 일반 권한으로 열어 Adobe Reader에서 반응이 없던 문제를 해결했다(doc/01 8절). 이를 위해 앱 대상이
  `net10.0-windows10.0.19041.0`(Windows 10 2004 이상)로 올라갔다.

## 12. 휴리스틱 평가 세 차례와 수정 (2026-10-13)

화면을 직접 조작·캡처해 Nielsen 휴리스틱으로 평가하고, 심각도 2 이상은 모두 수정했다.

| 차수 | 주요 수정 |
|---|---|
| 1차 | 알림 막대 종류(성공/경고)와 자동 닫힘, 여러 줄 붙여넣기 확인, 터미널 선택이 출력 따라 이동, 터미널 도움말 아이콘, 셸 변경 시 즉시 재시작, 색 입력 오류 안내, 자체 확인 창, 휴지통 항목 수/용량, 탐색기 최소 높이 |
| 2차 | 주소창 오류 시 입력 경로 유지, 열 폭 자동 조정, 알림 막대를 탐색기 위에 겹쳐 표시(화면이 밀리지 않음), 큰 글자에서 최소 창 크기 확대, 라이트 테마 보조 글자 대비 4.5:1 이상 |

## 13. 다국어 지원 (2026-10-13)

한국어/English를 설정 창에서 바꾸며 앱을 다시 켜지 않아도 즉시 적용된다. 구조는 doc/01 6절, 저장 위치는 doc/00 6절.
번역하지 않은 것: 개발자용 로그, 내부 예외 문구, Windows가 만드는 오류 설명(Windows 표시 언어를 따름). 영어 문구는 직접 작성한 것이라 어색한 표현이 있을 수 있다.

## 14. 릴리스 (2026-10-13)

GitHub Actions `release.yml`이 태그 푸시로 빌드·테스트·릴리스를 자동화한다. 첫 릴리스 `v1.0.0`(exe 61.4 MB, zip 56.2 MB, SHA256SUMS.txt)을 만들었다 (doc/00 5절).
서명하지 않은 exe라 처음 받은 사용자에게 SmartScreen 경고가 뜰 수 있다.

## 15. 코드 구조 정리

복잡도가 높았던 메서드를 나눴다: `ExplorerViewModel`의 폴더 크기 계산(캐시 선적용/백그라운드 계산 분리), 이동 실패 처리, 붙여넣기, `TerminalControl`의 선택 영역 처리·텍스트 추출,
`MainViewModel` 생성자의 이벤트 연결. 동작은 바꾸지 않았고 단위 테스트로 확인했다. `MainViewModel`(약 600줄)은 여러 책임(정보 막대·설정·즐겨찾기·드라이브)을 가진 큰 클래스로 남아 있다(분리하려면 화면 바인딩과 자동화 테스트까지 바꿔야 해서 미룸).
